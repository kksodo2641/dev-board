# Domain Design

## 개요

본 문서는 Dev Board 프로젝트의 핵심 도메인, 도메인 관계 및 비즈니스 규칙을 정의하기 위한 문서이다.

---

## 설계 원칙

- 객체 중심으로 도메인을 모델링한다.
- 비즈니스 규칙은 가능한 한 도메인 중심으로 관리한다.
- 삭제 정책은 일관성을 위해 Soft Delete 전략을 우선 적용한다.
- 권한 정책(USER, ADMIN)을 명확히 분리한다.

---

## 공통 엔티티 정책

모든 주요 엔티티(Member, Board, Comment, BoardLike, UploadFile)는 생성일시와 수정일시를 관리한다.

- createdAt: 생성일시
- updatedAt: 수정일시

---

## 도메인 관계 상세

### 1. Member ↔ Board

- 하나의 Member는 여러 개의 Board를 작성할 수 있다.
- 하나의 Board는 반드시 하나의 Member에 의해서만 작성된다.

**Cardinality: One-to-Many(1:N)**

### 2. Member ↔ Comment

- 하나의 Member는 여러 개의 Comment를 작성할 수 있다.
- 하나의 Comment는 반드시 하나의 Member에 의해서만 작성된다.

**Cardinality: One-to-Many(1:N)**

### 3. Board ↔ Comment

- 하나의 Board는 여러 개의 Comment를 가질 수 있다.
- 하나의 Comment는 반드시 하나의 Board에만 속한다.

**Cardinality: One-to-Many(1:N)**

### 4. Comment ↔ Comment

- 하나의 Comment는 여러 개의 대댓글을 가질 수 있다.
- 하나의 대댓글은 하나의 부모 Comment를 가진다.
- 최상위 댓글은 부모 Comment를 가지지 않는다.
- 댓글과 대댓글은 동일한 Comment 도메인으로 관리한다.

**Cardinality: One-to-Many(1:N, Self Reference)**

### 5. Board ↔ UploadFile

- 하나의 Board는 여러 개의 UploadFile을 가질 수 있다.
- 하나의 UploadFile은 반드시 하나의 Board에 속한다.

**Cardinality: One-to-Many(1:N)**

### 6. Member ↔ Board (좋아요 관점)

- 하나의 Member는 여러 개의 Board에 좋아요를 누를 수 있다.
- 하나의 Board는 여러 Member로부터 좋아요를 받을 수 있다.
- 이같은 다대다 관계는 중간 테이블 BoardLike를 통해 해소한다.

**Cardinality: Many-to-Many(M:N)**

### 7. Member ↔ BoardLike

- 하나의 Member는 여러 개의 BoardLike를 가질 수 있다.
- 하나의 BoardLike는 반드시 하나의 Member에 속한다.
- 동일 회원은 동일 게시글에 대해 하나의 BoardLike만 가질 수 있다.

**Cardinality: One-to-Many(1:N)**

### 8. Board ↔ BoardLike

- 하나의 Board는 여러 개의 좋아요를 가질 수 있다.
- 하나의 BoardLike는 반드시 하나의 Board를 대상으로 한다.

**Cardinality: One-to-Many(1:N)**

## 핵심 도메인

### 1. Member

#### 역할

- **회원**을 나타내는 도메인

#### 주요 책임

- 회원가입
- 회원탈퇴
- 로그인
- 로그아웃
- 게시글 작성
- 댓글 작성
- 좋아요 등록

#### 비즈니스 규칙

##### 회원가입

- 회원가입 시 이메일, 비밀번호, 닉네임, 성별을 입력받는다.
- 이메일을 로그인 ID로 사용한다.
- 이메일 형식 검증을 수행한다.
- 이메일은 중복될 수 없다.
- 닉네임은 중복될 수 없다.
- 탈퇴 회원의 이메일/닉네임은 재사용될 수 없다.
- 비밀번호는 최소 8자 이상이어야 한다.
- 비밀번호는 BCrypt 해시 형태로 저장한다.
- 닉네임은 2글자 이상, 30자 이하로 제한한다.
- 성별은 `남성`, `여성`, `선택안함` 중 하나를 선택할 수 있다.
- 회원가입 시 USER 권한을 부여한다.

##### 로그인/로그아웃

- 로그인 시 이메일, 비밀번호를 입력받는다.
- 존재하지 않는 이메일과 비밀번호 불일치는 동일하게 처리한다.
- 탈퇴한 회원은 로그인할 수 없다.
- 로그인 성공 시 세션을 생성한다.
- 로그아웃 시 로그인 상태를 해제한다.

##### 마이페이지

- 회원은 마이페이지에서 자신의 정보를 조회할 수 있다.
- 회원 상태, 권한, 이메일, 닉네임, 성별 정보를 확인할 수 있다.
- 비로그인 사용자는 마이페이지에 접근할 수 없다.
- 비로그인 사용자가 접근하는 경우, 로그인 페이지로 이동한다.
- 로그인 성공 시 원래 요청한 페이지로 복귀할 수 있다.
- ACTIVE 회원만 로그인 사용자로 간주한다.

##### 회원정보 수정

- 회원은 마이페이지에서 자신의 정보를 수정할 수 있다.
- 닉네임과 성별만 수정 가능하다.
  - 닉네임
    - 닉네임은 시스템 전체에서 유일해야 한다.
    - 다른 회원이 사용 중인 닉네임으로 변경할 수 없다.
    - 길이는 2자 이상, 30자 이하로 제한한다.
  - 성별
    - 성별은 자유롭게 변경할 수 있다.
- 이메일은 로그인 ID 역할을 하므로 수정할 수 없다.
- 권한은 수정할 수 없다.
- 상태는 수정할 수 없다.
- 탈퇴 회원은 회원정보를 수정할 수 없다.

##### 회원탈퇴

- 회원은 스스로 탈퇴할 수 있다.
- 회원탈퇴 시 복구할 수 없다.
- 회원탈퇴 시 Soft Delete를 적용한다.
- 탈퇴한 회원의 작성 게시글 및 댓글은 유지한다.
- 탈퇴한 회원의 이메일과 닉네임은 재사용할 수 없다.

### 2. Board

#### 역할

- **게시글**을 나타내는 도메인

#### 주요 책임

- 게시글 작성
- 게시글 조회
- 게시글 조회수 증가
- 게시글 수정
- 게시글 삭제

#### 비즈니스 규칙

##### 게시글 작성

- 게시글 작성 시 제목, 내용, 카테고리를 입력받는다.
- 게시글은 반드시 하나의 카테고리를 선택해야 한다.
- 게시글 제목과 내용은 필수 입력값이다.
- 게시글 제목은 최대 100자까지 입력할 수 있다.
- 일반 사용자는 공지사항 카테고리를 선택할 수 없다.
- 공지사항은 관리자만 작성할 수 있다.

##### 게시글 조회

- 로그인 여부와 관계없이, 누구나 게시글을 조회할 수 있다.
- 삭제된 게시글은 상세 조회할 수 없다.
- 게시글 상세 화면 조회 시 조회수를 증가시킨다.
- 쿠키 기반으로 24시간 동안 동일 게시글의 조회수 중복 증가를 방지한다.

향후 검토 예정

- 삭제 게시글 상세 조회 허용 여부는 추후 재검토한다.
- 삭제 게시글 상세 조회를 허용할 경우, 게시글 본문 숨김 및 댓글 유지 정책을 함께 검토한다.

##### 게시글 목록

- 게시글은 최신순으로 조회한다.
- 삭제된 게시글도 목록에서 조회할 수 있다.
- 삭제된 게시글은 `삭제된 게시글입니다.` 형태로 표시한다.
- 비회원도 게시글 목록을 조회할 수 있다.
- 공지사항은 목록에서 `[공지]` 라벨과 강조 색상을 통해 시각적으로 구분한다.

##### 게시글 페이징

- 게시글 목록은 페이지 단위로 조회한다.
- 페이지 번호는 1부터 시작한다.
- 잘못된 페이지 번호는 유효한 범위로 보정한다.
- 페이지 이동은 이전/다음 페이지 방식을 사용한다.
- 페이지 번호를 눌러 특정 페이지로 이동할 수 있다. 

##### 게시글 수정

- 게시글 수정 시 제목, 내용, 카테고리를 수정할 수 있다.
- 게시글 작성자만 수정할 수 있다.
- 관리자는 다른 회원의 게시글을 수정할 수 없다.
- 공지사항 카테고리로의 변경은 관리자만 가능하다.

##### 게시글 삭제

- 게시글 작성자 또는 관리자만 삭제할 수 있다.
- 게시글 삭제 시 Soft Delete를 적용한다.

##### 공지사항

- 공지사항 게시글 기능을 제공한다.
- 공지사항 게시글은 관리자만 작성할 수 있다.

향후 확장 고려

- 운영 정책이 필요한 경우, 공지사항(NOTICE)과 고정(PINNED) 정책을 분리하는 방안을 고려한다.

##### 첨부파일

- 첨부파일 업로드를 지원한다.
- 게시글당 여러 개의 첨부파일을 등록할 수 있다.
- 등록된 첨부파일은 다운로드할 수 있다.

---

### 3. Comment

#### 역할

- **댓글 및 대댓글**을 나타내는 도메인

#### 주요 책임

- 댓글 작성
- 댓글 조회
- 댓글 수정
- 댓글 삭제
- 대댓글 작성

#### 비즈니스 규칙

##### 댓글 작성

- 로그인한 회원만 댓글을 작성할 수 있다.
- ACTIVE 회원만 댓글을 작성할 수 있다.
- ACTIVE 게시글에만 댓글을 작성할 수 있다. 
- 삭제된 게시글에는 댓글을 작성할 수 없다.
- 댓글 작성 시 내용만 입력받는다.
- 댓글 내용은 필수 입력값이다.
- 공백으로만 이루어진 문자열은 허용하지 않는다.
- 댓글 내용은 최대 2,000자까지 작성할 수 있다.

##### 댓글 조회

- 게시글의 댓글과 대댓글을 함께 조회한다.
- 비회원도 댓글 목록을 조회할 수 있다.
- 화면에서는 부모 댓글 아래에 대댓글이 표시되도록 제공한다.
- 삭제된 댓글은 목록에서 제거하지 않는다.
- 삭제된 댓글은 `삭제된 댓글입니다.` 형태로 표시한다.
- 삭제된 댓글의 대댓글은 계속 조회할 수 있다.

##### 댓글 수정

- 댓글 작성자만 수정할 수 있다.
- 관리자는 다른 회원의 댓글을 수정할 수 없다.
- 댓글 내용만 수정할 수 있다.
- 삭제된 댓글은 수정할 수 없다.

##### 댓글 삭제

- 댓글 작성자 또는 관리자만 삭제할 수 있다.
- 댓글 삭제 시 Soft Delete를 적용한다.
- 삭제된 댓글은 다시 삭제할 수 없다.
- 삭제된 댓글은 목록에서 제거하지 않고, 삭제 상태로 표시한다.

##### 대댓글

- 대댓글은 동일한 Comment 도메인으로 관리한다.
- 대댓글은 최대 1단계까지만 허용한다.
  - 댓글에는 대댓글을 작성할 수 있다.
  - 대댓글에는 다시 대댓글을 작성할 수 없다.
- 대댓글은 현재 게시글에 속한 최상위 댓글에만 작성할 수 있다.
- 다른 게시글의 댓글에는 대댓글을 작성할 수 없다.
- 삭제된 댓글에도 대댓글을 작성할 수 있다.

##### 향후 확장 고려

- 댓글 좋아요(CommentLike) 기능을 추가할 수 있다.

---

### 4. BoardLike

#### 역할

- 게시글 **좋아요**를 나타내는 도메인

#### 주요 책임

- 좋아요 등록
- 좋아요 취소

#### 비즈니스 규칙

- 동일 회원은 동일 게시글에 한 번만 좋아요를 누를 수 있다.
- 좋아요 취소가 가능하다. 
- 좋아요 취소 시 해당 BoardLike를 삭제(Hard Delete)한다.
- 좋아요 중복 등록을 방지한다.

---

### 5. UploadFile

#### 역할

- 게시글 **첨부파일**을 나타내는 도메인

#### 주요 책임

- 파일 업로드
- 파일 다운로드

#### 비즈니스 규칙

- 게시글당 여러 개의 파일을 업로드할 수 있다.
- 업로드된 파일은 다운로드할 수 있다.
- 게시글이 Soft Delete 되더라도 첨부파일 정보는 유지한다.

## 권한 정책

### 1. USER

- 본인 게시글 수정 가능
- 본인 게시글 삭제 가능
- 본인 댓글 수정 가능
- 본인 댓글 삭제 가능

### 2. ADMIN

- 공지사항 작성 가능
- 모든 게시글 삭제 가능
- 모든 댓글 삭제 가능
- 다른 회원 게시글 수정 불가
- 다른 회원 댓글 수정 불가

향후 확장 고려 사항

- 회원 상태(ACTIVE / DELETED) 관리 가능

## 삭제 정책

도메인 간 참조 무결성과 이력 보존을 위해, Member, Board, Comment는 Soft Delete를 적용한다.

| 삭제 정책       | DB 삭제 여부 | 대상 도메인                       | 상태               |
|-------------|----------|------------------------------|------------------|
| 보존          | 유지       | UploadFile                   | 없음               |
| Hard Delete | 삭제       | BoardLike                    | 없음               |
| Soft Delete | 유지       | Member<br/>Board<br/>Comment | ACTIVE → DELETED |

## 인증 및 인가 정책

- 이메일 기반 로그인을 사용한다.
- 비밀번호는 BCrypt 해시값으로 저장한다. 절대 평문 비밀번호를 서버에 저장하지 않는다.
- 세션 기반 로그인을 사용한다. (향후 토큰 방식 교체 고려)
    - 로그인 성공 시 세션을 생성한다.
- 로그인 검증과 사용자 식별 책임을 분리한다.
- USER / ADMIN 권한 기반 접근 제어를 적용한다.
- 비회원도 게시글 목록, 게시글 상세, 댓글 목록은 조회할 수 있다.
- 게시글 작성/수정/삭제 및 댓글 작성/수정/삭제는 로그인 사용자만 수행할 수 있다.
